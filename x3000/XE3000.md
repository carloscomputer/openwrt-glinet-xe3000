# GL-XE3000 (Puli AX) build of this tree

This tree is a 1:1 copy of vjt/openwrt-glinet-x3000 (tag `jeeves-r14`, which is already based on OpenWrt v25.12.6 plus newer branch commits),
with the differences below. The directory is still called `x3000/` on purpose,
so that vjt's updates stay a plain rebase.

1. `x3000/config.common` selects the `glinet_gl-xe3000` device profile.
2. `x3000/lib/feed.sh` names the XE3000 image files and points the release
   tooling at this fork's own apk feed (the `gh-pages` branch of this repository) and signing key.
3. `x3000/feeds.conf` pins the package feeds to the commits of OpenWrt
   v25.12.6 when the tree was rebased onto that release; otherwise it is
   vjt's file unchanged.

4. `x3000/config.common` selects extra packages for both the private and the
   public image (OpenVPN incl. its kernel module, WireGuard, Tailscale), see the
   marked block at its end.
5. `x3000/xe3000-packages.txt` (optional) lists own package sources: git URL,
   pinned commit, and whether the package goes into the image or is only built as
   an .apk. They are wired into `x3000/custom-feeds.txt` and `x3000/config.common`.
6. `x3000/files-common/etc/uci-defaults/90-x3000-wwan` points the `wwan` default at the modem's device path `/sys/devices/platform/soc/11200000.usb/usb1/1-1/1-1.2`. vjt hard-codes the GL-X3000's PCIe path; on a GL-XE3000 the modem was seen on USB.

The GL-X3000 and GL-XE3000 share one device tree include
(`mt7981a-glinet-gl-x3000-xe3000-common.dtsi`), which carries
`pcie_port_pm=off`. That fix, and vjt's MHI/PCIe modem patches, are for the GL-X3000, where the
modem sits on PCIe. On the GL-XE3000 checked here the PCIe link is down and the modem
enumerates on USB (QMI via `qmi_wwan`, AT ports `ttyUSB0-3`); those parts stay in the
stack unchanged and are harmless, but they do nothing for the XE3000's modem.

The 5G watchdog and its Prometheus collector come from `quectel-5g-tools`
unchanged: metrics are `quectel_watchdog_*` (alert on
`quectel_watchdog_probe_ok == 0`). After installing or upgrading the package,
run `/etc/init.d/prometheus-node-exporter-lua restart`, because the exporter
caches its collectors at start.
